# Mollie Terminal for WooCommerce 2.0.0

This is the 2.0 version of Mollie Terminal for WooCommerce, made for WooCommerce POS 2.0. It needs WooCommerce POS Pro 2.0.0 or newer: on an older Pro, or without Pro, the plugin does nothing and shows an admin notice. Mollie Terminal is no longer offered on the shop's web checkout; it works in the POS only.

## Changed

- **WooCommerce POS Pro 2.0.0 or newer is required.**
- **Web checkout is removed.** Mollie Terminal no longer appears on the shop's checkout, and the "Enable Mollie Terminal for web checkout" setting is gone. You take terminal payments from the terminal tile on the POS keypad, or from the POS order-pay page (the Legacy tab). **POS → Settings → Checkout** is the only place to switch it on or off.
- **The Legacy tab uses the POS's shared payment panel.** A payment taken there is recorded by the POS like a keypad payment, and the POS handles its status checks, cancel and refunds. While an on-screen QR method (iDEAL or Bancontact) is enabled, the plugin's own panel stays, because the shared panel cannot show a QR code yet.

## Added

- **A terminal tile on the POS keypad.** It uses the reader settings you already have in the gateway settings. Tips added on the terminal are recorded on the order as a fee.
- **Pending refunds now settle in the POS.** Mollie refunds start out pending. Before, the POS and the order note kept saying pending until someone checked the Mollie dashboard. Now WooCommerce POS Pro checks each pending refund every ten minutes and records it as refunded or failed, with an order note.

## Fixed

- **No double charge when Mollie does not answer.** If Mollie did not answer a payment request, the POS treated it as refused, and a retry could charge the customer twice. The payment now stays pending, and a retry gets back the payment Mollie already made.
- **No second refund when Mollie does not answer.** If Mollie did not answer a refund request, a retry made a new refund. The plugin now finds the refund Mollie already made.
- **Refunds across two terminal payments on one order.** When one refund covered two Mollie payments, only the first payment was refunded at Mollie, while the POS showed the whole amount as returned. Each payment now gets its own Mollie refund.
- **Two payments on one sale.** With an on-screen QR method enabled, the old panel no longer starts a Mollie payment on a sale that already has a live payment recorded at the till. The keypad tile no longer sends a payment to the terminal while an old-panel payment is still open on the order.
- **Installing from the zip.** The release zip now holds a single `mollie-terminal-for-woocommerce/` folder, so WordPress 7.1.4 and newer installs it into the plugin's own folder instead of a folder with a random suffix.

## Upgrade

- Install or update WooCommerce POS Pro to 2.0.0 or newer.
- If you took Mollie Terminal payments on the web checkout, take them in the POS from now on.
- Terminal payments that were still in progress in the old panel when you update are handed over to the POS and finish there. A browser tab still showing the old panel asks the cashier to reload. With iDEAL or Bancontact QR enabled, nothing is handed over: the old panel finishes its own payments.
- Refunds recorded before this update keep working as they are.
